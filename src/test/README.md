# 预约模块测试

## 第二条用例 RES-H-002

Reservation002Test 测试正常预约羽毛球馆，方法为等价类划分（有效场馆）。
使用真实数据库中的羽毛球馆，单价须为100元/小时，营业时间须包含14:00—16:00。
自动注册缺失的user01，通过登录接口建立会话，选择未来30天内场馆无订单且用户时段无冲突的一天。
提交后查询数据库，验证新订单为2小时、200元、未审核，订单保留供前端查看。

```text
mvn -Dtest=Reservation002Test test
```

也可在IDE中单独运行Reservation002Test。此测试同样使用MockMvc发送请求，不操作浏览器。

## 第一条用例 RES-H-001

Reservation001Test 对应 RES-H-001，连接 application.yml 中配置的真实 MySQL。
须先启动 MySQL，并准备名为“篮球馆”的场馆（200元/小时，营业时间包含09:00—11:00）。
测试自动检查user01是否存在：不存在时通过注册接口创建普通用户，初始密码为 TestUser01!；存在则复用，不修改密码。
账号和订单都保存在真实数据库。缺少场馆或场馆配置不符合用例时测试失败。

在 IDE 中运行测试方法，或在项目根目录运行：

```text
mvn -Dtest=Reservation001Test test
```

测试使用真实登录逻辑和现有账号记录建立会话，选择未来30天内场馆无订单的一天预约09:00—11:00。
若所选时段用户已有其他场馆预约，会停止提交。
MockMvc仅发送测试请求；Controller、Service、DAO均由Spring加载，数据实际写入MySQL，不使用Mockito或独立测试数据库。
不执行事务回滚或清理，每次成功运行保留一笔真实订单，控制台输出订单编号和日期。
请勿并发运行；即使提交后的断言失败，已提交订单仍可能保留，应检查数据库。

完成后在网站登录user01，通过“我的预约”查看，其他普通用户的列表不会显示这笔订单。
无需先启动网站即可运行测试。本脚本不操作浏览器控件。
